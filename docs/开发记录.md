# Genshin Impact 开发记录

## 2026-08-09

- 建立 iPhone Scriptable 原神大号组件项目。
- 接入 `LPL-Design-System` 共享依赖接口：`resolvePalette`、`typography`、`layout`、`applyCardBackground`。
- 完成 HoYoLAB Cookie 的 Scriptable Keychain 保存机制。
- 完成原粹树脂、每日委托、洞天宝钱和周本提醒的初版 UI。
- 新增 `Installer.js`，从 GitHub main 分支按依赖顺序安装设计系统和主组件。
- 使用正式版 `LPL-Design-System.js` v2.9.1 替换项目内兼容实现；主组件内部保留业务专用布局辅助，不再扩展共享依赖接口。
- 修复 Scriptable `WidgetStack` 不支持 `heightAnchor/widthAnchor` 导致的进度条崩溃，改用 `Size`。
- 主脚本重命名为 `Genshin Widget.js`，安装器更新时会移除旧名称。
- 修复已有 Keychain 配置导致直接运行不再显示 Cookie 输入的问题：App 内运行始终打开配置，组件刷新不弹窗。
- 无缓存且接口请求失败时改为显示错误原因，不再展示误导性的全零数据。
- 数据源由国际服 HoYoLAB 切换为国服米游社实时便笺，默认服务器改为 `cn_gf01`。
- 实现 client type 5 的 DS2/MD5 动态签名，并使用米游社 LToken Cookie。
- 周本区域改为显示接口返回的减半奖励剩余次数，不再使用静态周本名称。
- 针对 1034 风控补齐稳定的 `x-rpc-device_id`、`x-rpc-device_fp` 和米游社设备请求头。
- 配置页支持读取完整 Cookie 中的 `DEVICEFP` 与 `_MHYUUID`，并将米游社版本更新为 `2.109.0`。
- 增加接口诊断：显示 HTTP 状态、retcode 和脱敏响应摘要，区分 Cookie 登录失败、JSON 解析失败与风控响应。
- 使用无效测试 Cookie 验证当前国服请求可正常返回 `HTTP 200 / retcode 10001`，确认 DS2 与基础请求头可被服务端解析。
- 安装器改为原生版本确认界面，显示本地/远端版本、设计系统版本与更新说明，并明确重装会保留设置、Cookie 和缓存。
- 新增 `release.json` 作为安装器远端发布信息源，主组件加入可解析的 `WIDGET_VERSION`。
- 根据真机诊断确认 `retcode 5003` 与设备指纹校验有关；移除随机 DEVICEFP，迁移时清除旧版随机值，只发送 Cookie 提取或用户输入的真实 13 位值。
- 真机使用真实浏览器 DEVICEFP 仍返回 5003，确认浏览器指纹与脚本固定设备头混用并不可靠；改为调用 `public-data-api.mihoyo.com/device-fp/api/getFp` 为稳定设备 ID 自动申请配套指纹，并在 5003 时刷新后重试。
- 服务端签发的配套指纹重试后仍返回 5003；增加 `game_record/genshin/aapi/widget/v2` iOS 小组件接口作为 5003/1034 自动回退，并合并显示双接口诊断。
- 使用无效测试 Cookie 验证 iOS 小组件接口无需 DS 即可进入鉴权流程并返回标准 `HTTP 200 / retcode 10001`。
- 主接口持续 5003 且 iOS 小组件接口返回 10001，确认浏览器 Cookie 缺少备用接口所需的 SToken 登录态。
- 新增米游社二维码授权流程：使用当前 Passport QR 接口直接取得 SToken v2，再换取 LToken 与 CookieToken，全程仅存入 Scriptable Keychain。
- 当前工作区已关联远程仓库：`https://github.com/braziliany/Genshin-Impact.git`。
- GitHub 远程仓库已完成首次推送，`main` 为安装器使用的发布分支。

## 2026-08-12

- 发布 1.4.0 开发版，修复洞天宝钱恢复时间为零时被误判为“已储满”的问题；现在仅在当前值达到接口最大值时显示满值状态。
- 将原周本卡片升级为紧凑的“周常与探索”状态卡，同时展示周本减半、探索派遣和参量质变仪。

- 设置页增加安全退出登录，删除 Keychain 凭据和组件缓存，但保留 UID、昵称与服务器设置。
- 发布 1.4.1 修正版：探索派遣的 `Finished` 仅显示为“已完成”，不再推断为“可领取”；主数字改为已使用派遣槽位，完成数量单独显示。
